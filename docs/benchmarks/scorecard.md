# Per-kind QC scorecard

Generated by `python3 -m procqc.audit.scorecard --out <this file>` from the saved runs (no model calls).
Every row uses the same definitions.

**Recordings**: total (with the error / without it), by the labels.

**Two settings for every check**
* *detector only*: every candidate counts as a flag.
* *detector + verifier*: only candidates the per-kind verifier confirmed count. Termination and wrong
  tool / object v2 are one check with no separate verifier; there, "detector only" also counts the
  low-confidence (needs-review) answers and "+ verifier" only the confident ones.

**Recording level** (the QC decision: is this recording sent back?)
* recording recall = recordings with the error that got any flag / recordings with the error
* false-alarm rate = recordings without the error that got a flag / recordings without the error
* recording precision = flagged recordings that have the error / flagged recordings

**Event level** (is the right thing flagged?): each labelled error is matched by at most one flag.
TP = labelled errors matched by a flag, FP = flags matching none, FN = labelled errors with no flag.
"Of the FP, labelled as another kind" counts false flags on a step that carries a label of a different
kind: the error is real but the annotators filed it elsewhere (a second egg as a measurement error).
Where a check reports one flag per substitution (wrong tool / object), that flag covers every labelled
step that used the same substitute.
Matching: termination one per recording; omission and misordering by step id; repeat and repeated
addition by step id and time overlap; off-graph addition by time overlap; wrong tool / object by step id,
or a later step that uses the same substitute (one flag per substitution).

**Own cost per recording**: the check's own model calls (candidates and verifier), averaged over the
recordings. The narration and match stage are shared by four checks and reported once, below the table.

**Reading notes**
* A "–" means undefined (nothing to divide by), e.g. recall on a data set with no positives.
* CaptainCook4D has no termination, addition or repeat labels: on those rows it measures false alarms only.
* Misordering event recall is low by construction: CaptainCook4D tags every step of an inverted block,
  the check reports the first inverted step. Use recording recall for misordering.
* Wrong tool / object: CaptainCook4D files substitutions under "Preparation Error" with spills, unwashed
  produce and incomplete steps; the gold is the labels whose note describes a substitution
  (`procqc/direct/wrongtool.py`, `gold`).
* Repeated additions (a second egg, a second spoonful) are reported as parameter deviations tagged
  `repeated_addition`; their gold labels are CaptainCook4D measurement errors stating a count above one
  ("2 instead of 1 egg", 17 labels on the 36 recordings with video).
